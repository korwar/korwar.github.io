# 제2차 한국전쟁

> 웹 브라우저에서 실행되는 실시간 전쟁 지휘 시뮬레이션 게임

플레이어는 한반도 전쟁을 지휘하는 위치에서 국군 각 부대에 명령을 내립니다. 직접 전투를 조작하지 않습니다. 사단·여단 단위로 공격, 방어, 지연전, 후퇴, 예비 같은 자세를 지시하고, 포병 사격 강도, 공군 작전 배분, 외교·동원 같은 전략 결정을 내립니다. 그러면 시뮬레이션이 전투 결과와 전선 이동을 실시간으로 계산합니다. 목표는 전선을 압록강·두만강까지 밀어 올려 한반도를 통일하는 것입니다.

> 이 게임은 가상의 시나리오를 다룬 전략 시뮬레이션입니다. 실제 작전계획이나 특정 국가·단체의 입장과 무관합니다.

## 1. 주요 특징

| 영역 | 내용 |
|---|---|
| **지휘 중심 게임플레이** | 국군 사단·여단 70여 개를 지도 위 버튼으로 선택해 부대 전체 또는 예하 여단별로 지시합니다. |
| **실시간 전선 시뮬레이션** | 한반도를 약 5km 격자로 나누고, 양측 전투력 비교에 따라 격자 소유가 바뀌며 전선이 움직입니다. |
| **시간 제어** | 1배속 기준 5초가 하루입니다. 1·2·4·8·16배속과 일시정지를 지원하며, 일시정지 중에도 지시할 수 있습니다. |
| **확전 요소** | 미군 순차 증원, 중국군 개입(최대 4파), 북한 특수작전군의 반복 침투, 교도대 동원, 대량살상무기 위협이 있습니다. |
| **전체 공유 학습 AI** | 북한군은 모든 플레이어의 전쟁 기록을 하나의 교리로 학습합니다. 같은 전술이 반복될수록 대응이 강해집니다. |
| **국민 지지도** | 사상자·민간인 피해·교착·영토 상실이 누적되면 지지도가 떨어지고, 0이 되면 패배합니다. |
| **위험 경보** | 패전 직전에는 지도가 붉게 점멸하고, 상단에 노란 경보 메시지가 표시됩니다. |
| **시나리오별 엔딩** | 결과에 따라 6가지 엔딩 중 하나가 검은 화면 위 페이드 텍스트로 흐릅니다. |
| **명예의 전당** | 승전 기록을 9개 분야로 순위를 매깁니다. 순위표에는 `닉네임 (IPv4 앞 두 자리)` 형식으로 표시됩니다. |
| **오프라인 대체 동작** | 서버에 연결할 수 없으면 브라우저 저장소만 쓰는 모드로 자동 전환되어 계속 플레이할 수 있습니다. |

## 2. 시스템 구성

정적 프런트엔드와 소형 API 서버를 분리한 구조입니다.

```
┌─────────────────────────────┐          ┌──────────────────────────────────┐
│  GitHub Pages               │  HTTPS   │  Oracle Cloud Always Free VM     │
│  (정적 호스팅)              │ ───────▶ │                                  │
│                             │   JSON   │  Caddy  ── 자동 HTTPS, 프록시    │
│  index.html (단일 파일)     │ ◀─────── │    │                             │
│  ├ 게임 화면·UI             │          │    ▼  127.0.0.1 only             │
│  ├ 전쟁 시뮬레이션 엔진     │          │  Node.js API (의존성 없음)       │
│  └ 학습 AI 적용·기록 생성   │          │    ├ data/brain.json   공유 교리 │
└─────────────────────────────┘          │    └ data/rankings.json 명예의 전당│
                                         └──────────────────────────────────┘
```

**설계 원칙은 "계산은 브라우저, 공유 상태만 서버"입니다.**

- 전투 시뮬레이션 전체가 플레이어의 브라우저에서 돌아갑니다. 서버는 게임 시작·종료 시점에만 짧은 요청을 받습니다.
- 그래서 무료 서버(1/8 OCPU, 1GB RAM)로도 운영이 가능합니다.
- 프런트엔드와 서버가 같은 학습·랭킹 로직(`shared/`)을 공유해, 양쪽 계산 결과가 항상 일치합니다.
- 서버는 외부 패키지 없이 Node.js 기본 모듈만 사용합니다. 의존성 설치나 공급망 관리가 필요 없습니다.

### 한 판의 데이터 흐름

```
[시작하기] ──▶ POST /api/game/start ──▶ 일회용 토큰 + 현재 공유 교리 수신
     │
     ▼
브라우저에서 전쟁 진행 (서버 통신 없음)
     │
     ▼
[종전] ──▶ POST /api/game/end (작전 보고서)
               ├ 경과 시간·수치 타당성 검사
               ├ 통과 시 공유 교리에 학습 반영
               └ 승전이면 랭킹 진입 여부 판정
     │
     ▼
[닉네임 입력] ──▶ POST /api/rank/submit ──▶ 금지어 검사 후 명예의 전당 등록
```

## 3. 저장소 구조

```
second-korean-war-frontend/
├── src/
│   ├── template.html   화면 골격 (메인 메뉴·게임 화면·모달·엔딩), 빌드 시 아래 파일이 삽입됨
│   ├── style.css       전체 스타일, 위험 경보 애니메이션, 소형 화면 레이아웃
│   ├── data.js         지도 폴리곤, 도시, 국군·북한군·미군·중국군 전투서열
│   ├── core.js         시뮬레이션 엔진 (전투·이동·영토·보급·AI·지지도·종전 판정)
│   ├── api.js          서버 통신, 실패 시 오프라인 모드 전환
│   ├── ui.js           Canvas 지도 렌더링, 부대 버튼, 지휘 패널, 위험 경보
│   └── menu.js         메인 메뉴, 명예의 전당, 프롤로그·엔딩 연출, 기기 판정
├── shared/
│   ├── brain.js        북한군 학습 AI (브라우저·서버 공용)
│   └── rank.js         랭킹 분야·점수 계산·닉네임 검증 (브라우저·서버 공용)
├── build.py            모든 소스를 단일 index.html 로 합치는 빌드 스크립트
└── .github/workflows/pages.yml   push 시 자동 빌드·배포
```

서버 측 구성은 다음과 같습니다.

```
backend/
├── server.js                   API 서버 (Node.js 기본 모듈만 사용)
├── shared/                     프런트엔드와 동일한 brain.js, rank.js
├── config/banned_words.txt     닉네임 금지어 목록 (실행 중 수정 시 즉시 반영)
└── deploy/                     설치·업데이트 스크립트 (systemd, Caddy, 백업)
```

- **규모:** 프런트엔드 소스는 주석을 포함해 약 2,500줄입니다.
- **결과물:** 빌드하면 외부 라이브러리 없이 HTML·CSS·JavaScript가 모두 들어간 `index.html` 파일 하나가 됩니다.

### 빌드 방식

`build.py`는 `template.html`의 자리표시자(`/*CSS*/`, `/*CORE*/` 등)에 각 소스 파일을 순서대로 끼워 넣습니다. 이때 API 서버 주소도 함께 주입합니다. 번들러나 트랜스파일러는 쓰지 않습니다.

```
API_BASE=https://api.example.org python3 build.py   →   dist/index.html
```

## 4. 시뮬레이션 엔진

`src/core.js`는 DOM에 의존하지 않는 순수 로직입니다. 그래서 브라우저 밖(Node.js)에서도 같은 엔진으로 대량 시뮬레이션을 돌려 밸런스를 검증할 수 있습니다.

### 시간 단위
- 엔진은 **1시간 단위 스텝**으로 진행합니다.
- 전투·이동은 매시간, 영토 변화는 3시간마다, 적 AI 판단은 6시간마다 처리합니다.
- 보급·지지도·증원·침투·종전 판정은 매일 처리합니다.

### 지도 모델
- 위도 33.0–43.1°, 경도 124.2–130.8° 범위를 0.05° 격자(132×202칸)로 나눕니다.
- 각 칸에는 육지 여부, 소유 측, 산악, 해안, 요새화 여부를 저장합니다.
- 전선은 서로 다른 소유 칸이 맞닿은 경계로 자동 계산됩니다.

### 부대 모델
- 부대는 사단·여단 단위이고, 예하에 여단·직할대를 가집니다.
- 각 예하 단위에는 장교·부사관·병사 수, 전차, 장갑차, 야포, 다연장로켓, 포탄 재고가 있습니다.
- 전투력은 병력, 장비, 측별 질적 계수, 사기, 보급 상태, 자세(공격·방어 등)를 곱해 계산합니다.

### 전투와 영토
1. 24km 이내의 적대 부대 쌍은 근접 교전을 하고, 사거리 안에 있으면 포격전을 합니다. 손실은 양측 전투력 비율의 0.7제곱에 비례합니다.
2. 각 부대는 주변 칸에 공격력과 방어력을 거리 가중치로 뿌립니다.
3. 적 영토와 맞닿은 칸에서 공격력이 방어력을 넘으면 점령 진척도가 쌓입니다. 진척도가 1에 도달하면 칸의 소유가 바뀝니다.
4. 산악은 진척 속도를, 휴전선 북방 요새 지대는 방어력을 보정합니다.

### 보급과 포위
- 각 측 보급 거점(주요 도시)에서 자기 영토를 따라 연결된 칸만 '보급 연결' 상태가 됩니다.
- 보급이 끊긴 부대는 보급·사기가 떨어지고, 결국 투항합니다.
- 적 부대가 없는 고립 지역은 저항이 소멸한 것으로 보고 점령 처리합니다.

### 확전 이벤트

| 이벤트 | 내용 |
|---|---|
| **미군 증원** | 가상 일정에 따라 4개 제대가 남부 항구·기지로 전개합니다. |
| **중국 개입** | 북측 확보율, 북위 39.6° 이북에 들어간 아군 부대 수, 북상한 미군에 따라 위험도가 쌓입니다. 개입하면 최대 12개 제대가 4파에 걸쳐 진입합니다. |
| **특수작전군 침투** | 공중·해상·땅굴·점령지 유격 네 가지 방식으로 3~9일마다 1개 조씩 후방에 출현합니다. |
| **교도대 동원** | 북한 후방 집결지에서 동원사단이 주기적으로 편성됩니다. |
| **WMD** | 평양 접근, 북측 확보율 등에 따라 위협도가 오르며, 100에 이르면 사용됩니다. |

### 종전 판정과 엔딩

| 엔딩 | 조건 |
|---|---|
| 한반도 통일 | 북측 전역 확보, 중국 개입 없음 |
| 두 개의 군대를 넘어 | 중국 참전 후 통일 |
| 상처뿐인 통일 | 통일했지만 국민 지지도 20 미만 또는 국군 사상자 35만 명 초과 |
| 휴전 | 국민 지지도 0 |
| 패전 | 국군 통제 영토가 한반도 육지의 5% 미만 |
| 정전 | 플레이어가 항복 선택 |

## 5. 북한군 학습 AI

`shared/brain.js`에 구현되어 있습니다. 플레이어별이 아니라 **서버의 단일 교리 하나에 모든 플레이어의 전쟁이 누적**되는 방식입니다.

### 학습하는 것

| 학습 대상 | 다음 판에 반영되는 방식 |
|---|---|
| 국군 주공 축선 (서부·중부·동부) | 해당 축선의 요새 종심을 늘리고 기계화 예비대를 미리 배치 |
| 상륙 지점 | 자주 쓰인 해안에 수비 사단 배치, 근처 상륙 시 초기 피해 증가 |
| 공중작전 빈도 | 공수·공중강습 시 초기 피해 증가 |
| 침투 방식별 효과 | 효과가 컸던 방식을 더 자주 선택 |
| 교리 13개 항목 | 공세·역습·지연전 판단 기준, 예비대 투입 수와 반경, 침투·동원 주기 등 |

### 진화 방식
- **변이 후 선택:** 판마다 현재 최선 교리에서 로그정규 분포로 무작위 변이를 만들어 사용합니다. 결과가 북한군에게 더 유리했으면 그 변이를 새 최선 교리로 채택합니다.
- **변이 폭 감소:** 누적 전쟁 수가 늘수록 변이 폭(σ = 0.22/√세대, 최소 0.05)이 줄어 교리가 점차 수렴합니다.
- **기억의 감쇠:** 축선·상륙·침투 기억은 지수이동평균(가중치 0.2)으로 갱신합니다. 오래된 경향은 서서히 잊히고, 한 판이 전체를 뒤흔들지 않습니다.
- **숙련도:** 누적 전쟁 수에 비례해 북한군 전투효율 보정이 최대 +8%까지 오릅니다.
- **첫 판:** 기록이 없을 때는 사람이 설계한 기본 교리로 시작합니다.

### 북한군의 실시간 판단 (매 6시간)
- **부대별 자세:** 반경 45km 안의 아군·적군 전투력 비율, 잔존 병력, 보급 상태로 공격·방어·지연·후퇴를 정합니다.
- **예비대 투입:** 국군 공세 중 평양 방향으로 위협도가 가장 큰 축선을 골라, 가까운 예비대를 정면 후방에 투입합니다.
- **공세 전환:** 국군이 일정 기간 공세에 나서지 않으면 선제 공세로 전환하고, 이후에도 주기적으로 반격을 시도합니다.

## 6. 국민 지지도 모델

지지도는 매일 **목표 지지도**를 향해 12%씩 다가갑니다. 돌발 사건은 즉시 충격을 준 뒤 서서히 목표치로 돌아갑니다.

```
목표 = 68
     + 개전 결집 효과       12·e^(−일/25)
     − 장병 사상자          11·log₁₀(1 + 전사 환산 누적/1000)
                            (전사 1, 실종 0.7, 부상 0.25, 미군 ×0.3)
     − 민간인 피해           6·log₁₀(1 + 누적/2000)
     + 전과                 32·북측 확보율 (+ 평양 점령 8)
     − 전선 교착            진전 없이 10일 초과 시 하루 0.6씩 (최대 25)
     − 장기전 피로          D+45 이후 하루 0.12씩 (최대 15)
     − 남측 영토 피탈       피탈 비율 ×90 (서울 함락 시 추가 25)
     − 외부 악재            WMD 피격·중국 참전·동원령
```

사상자 항목을 로그로 둔 것은 의도적인 설계입니다. 초기 손실의 충격은 크게, 장기전 누적 손실은 점차 둔감하게 반영해 실제 여론의 체감 방식에 가깝게 만들었습니다.

## 7. 명예의 전당과 기록 검증

### 랭킹 분야 (9개)
- 종합 전공 점수
- 최단 기간 통일
- 최소 전쟁 비용
- 최소 민간인 피해
- 최소 국군 사상자
- 최소 국군 전사자
- 최고 종전 국민 지지도
- 최다 포로 획득
- 중국 개입 없는 최단 통일

각 분야는 전체와 난이도별(쉬움·보통·어려움)로 10위까지 표시합니다. 어느 순위표에도 남지 못한 기록은 자동으로 정리됩니다.

### 개인정보 최소화
- 저장하는 정보는 닉네임과 접속 IPv4 주소의 **앞 두 자리**뿐입니다. 전체 IP는 저장하지 않습니다.
- IP는 리버스 프록시가 실제 TCP 접속 주소로 넣어 주는 헤더만 신뢰하므로, 클라이언트가 위조할 수 없습니다.

### 닉네임 검증
- 1~12자, 한글·영문·숫자와 일부 기호만 허용하며, 중복은 허용합니다.
- 금지어 검사는 유니코드 정규화 후 공백·기호를 제거하고 대소문자를 무시해 '포함' 여부로 판단합니다. 숫자·기호 치환(0→o, 1→i, 3→e, 5→s, @→a)으로 피해 가는 경우도 걸러 냅니다.
- 같은 검사 함수를 브라우저(즉시 안내)와 서버(최종 판정) 양쪽에서 사용합니다.

### 기록 조작 방지
시뮬레이션이 클라이언트에서 돌기 때문에 서버는 보고서를 그대로 믿지 않고 다음을 검사합니다.

- **일회용 토큰:** 게임마다 발급하며, 재사용할 수 없습니다.
- **경과 시간:** 실제 경과 시간이 16배속으로 계산한 최소 시간보다 짧으면 거부합니다.
- **수치 타당성:** 전사자가 사상자보다 많으면 안 되고, 일수 대비 최소 사상자를 넘어야 합니다. 승전이면 최소 일수, 북측 확보율, 포로 상한도 확인합니다.
- **요청 빈도 제한:** IP별로 요청 간격을 제한합니다.
- **입력 범위 강제:** 모든 수치를 허용 범위 안으로 강제(clamp)합니다.

다만 계산이 브라우저에서 이뤄지는 구조상, 작정한 조작을 완전히 막을 수는 없습니다.

## 8. 화면 구성

| 화면 | 구성 |
|---|---|
| **메인 메뉴** | 시작하기, 게임 안내, 설정, 제작 정보. 오른쪽에 명예의 전당 |
| **프롤로그·엔딩** | 검은 화면에 흰 글자를 페이드 인·아웃. 건너뛰기 버튼 제공. 첫 줄의 연도는 실행 날짜를 따름 |
| **게임 화면** | 중앙 Canvas 지도와 부대 버튼 레이어. 오른쪽 상태 패널과 지휘 패널. 하단 작전 로그 |
| **위험 경보** | 지도 위 붉은 점멸 오버레이(위기 2초, 경고 3.2초 주기)와 상단 중앙 노란 메시지 |
| **결과 화면** | 전쟁 통계, 종합 점수, 학습 반영 결과, 랭킹 진입 시 닉네임 입력 |

### 렌더링 방식
- **지도:** 격자 소유 상태를 132×202 크기의 오프스크린 Canvas에 픽셀로 그린 뒤 확대해 씁니다. 해안선은 클리핑 경로로 다듬습니다. 영토가 바뀔 때만 다시 그립니다.
- **부대 버튼:** 클릭과 접근성을 위해 Canvas가 아닌 HTML 요소로 둡니다. 지도를 확대·축소해도 버튼 크기는 그대로입니다.
- **부대 휘장:** 부대 유형별 색상과 번호·애칭으로 SVG 휘장을 자동 생성합니다.

### 지원 기기
넓은 지도와 다수의 부대를 동시에 다루는 UI라 **PC 또는 대형 태블릿(1024×600 이상)** 을 대상으로 합니다.
- 스마트폰에서는 메인 메뉴와 명예의 전당만 볼 수 있고, 게임을 시작하면 플레이 불가 안내가 표시됩니다.
- 판정에는 화면 크기, 터치 전용 입력 여부, User-Agent를 함께 사용합니다.

## 10. 개발 방식

- **반복 개발:** 기획자의 요구사항을 바탕으로 AI 코딩 도우미와 대화하며 설계·구현·수정을 반복했습니다. 단계는 다음과 같습니다.
  1. 단일 HTML 프로토타입
  2. 난이도·학습 AI·지지도 모델 도입
  3. 메인 메뉴와 랭킹
  4. 서버 분리
  5. 경보·엔딩·기기 대응
- **헤드리스 검증:** 엔진이 DOM과 분리되어 있어 Node.js에서 수백 일 분량의 전쟁을 자동으로 돌려 볼 수 있습니다. 난이도별 승패 분포, 지지도 추이, 침투 빈도를 확인하며 계수를 조정했습니다.
- **UI 회귀 시험:** 헤드리스 브라우저(Playwright/Chromium)로 화면을 시험했습니다. 대상은 메인 화면, 프롤로그, 위험 경보, 엔딩, 랭킹 등록, 서버 장애 시 오프라인 전환, 스마트폰·태블릿 기기 판정입니다.
- **의존성 최소화:** 프런트엔드는 외부 라이브러리 없이 바닐라 JavaScript와 Canvas로, 서버는 Node.js 기본 모듈로만 작성했습니다.
- **무료 인프라:** GitHub Pages(정적 호스팅), Oracle Cloud Always Free VM, Caddy(무료 HTTPS 인증서 자동 갱신), DuckDNS(무료 도메인)로 운영 비용 없이 서비스합니다.

## 11. 로컬에서 실행해 보기

**오프라인 모드** (서버 없이 게임만):
```bash
python3 build.py
# dist/index.html 을 브라우저로 열기
```

**서버와 함께:**
```bash
# 터미널 1 — API 서버
cd backend
PORT=8787 ALLOWED_ORIGINS=http://localhost:8000 node server.js

# 터미널 2 — 프런트엔드
API_BASE=http://localhost:8787 python3 build.py
cd dist && python3 -m http.server 8000
# http://localhost:8000 접속
```

요구 사항은 Python 3과 Node.js 18 이상, 그리고 최신 데스크톱 브라우저(Chrome, Edge, Firefox, Safari)입니다.
